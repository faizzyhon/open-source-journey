## Not earned (yet) and how to actually earn them

### Pair Extraordinaire — co-author a commit

- **What's needed:** A commit with a `Co-authored-by: Name <email>` trailer where the email belongs to a real GitHub account.
- **How to legitimately earn it:** Pair-program with a friend, or co-author a doc/translation with another contributor. Faking it with a second email of yours is awkward and doesn't reflect a real collaboration.

### Galaxy Brain — answer accepted in a GitHub Discussion

- **What's needed:** Post a substantive answer in a public repo's Discussions tab; have the OP mark it as the accepted answer.
- **How to earn it:** Watch the Discussions tab of a repo whose subject matter you know well (your stack). Help someone with a real question. This one feels good when it happens.

### Starstruck — your repo gets 16 / 128 / 512 / 4096 stars

- **What's needed:** A repo you own attracts community attention.
- **How to earn it:** Build something genuinely useful. (This guide repo could plausibly attract stars over time if the content keeps getting better.)

### Public Sponsor — sponsor an open-source maintainer

- **What's needed:** A real GitHub Sponsorship (or one-time tip via the platform).
- **How to earn it:** Pick a maintainer whose work you actually use and sponsor them. Even a small amount counts.

## What I'd do differently

Earning Pull Shark/YOLO/Quickdraw on a personal repo is technically fine and harmless, but the badge that actually matters in a code review or job interview is **a merged PR to a project people use**. The EbookFoundation PR (see `case-studies/2026-05-ebookfoundation-12348.md`) is the one that does that work.

If you're starting from zero, I'd suggest: ship one real external PR first, then earn personal-repo badges as a side effect of building your own useful thing — not as the main event.
